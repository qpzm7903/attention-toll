# 多端同步：chrome.storage.sync + 设备分账

多台电脑需要共享注意力预算池（否则存在「设备跳跃漏洞」，与全局共享池的初衷矛盾）。同步走 `chrome.storage.sync`（零配置、零凭据，依赖 Chrome 登录 Google 账号），采用**设备分账**：每台设备只增写自己的消耗分桶（`u:<deviceId>`），全局消耗 = 各设备之和——只增计数器天然无写冲突，不需要合并算法。干预判定基于合并后的总和，接受分钟级同步延迟；放行状态与设置也同步（设置带时间戳最后写入胜出）。本地 `storage.local` 仍是本机全量数据的真身，sync 是尽力而为的交换层：未登录或不可达时退化为单机模式，插件功能不受影响。

本决策部分推翻了早先「纯本地存储」的非正式决策——隐私边界从「不出本机」放宽为「不出你的 Google 账号」。

## Considered Options

- WebDAV（坚果云等）——国内连通性更好、无配额焦虑，但需用户填服务器凭据、自行实现推拉与合并，成本明显更高；作者环境 Google 可达，已否决。
- 自建后端——完全自控但需要服务器与运维，对个人工具过重，已否决。

## Consequences

- sync 总配额 100KB / 单键 8KB：每设备只同步近 35 天统计与最近 30 条通行记录（超长文本截断），完整数据仍在各自本机。
- 刚换设备的头几分钟可能少算消耗；跨设备放行在延迟窗口内可能多拦一次——均已接受。
